Recognition Kernel

What this tool does

You describe a system — a body of rules, an ontology, a certification scheme — as a chain of seven links. The kernel then tells you which failure modes that system can have, and where.

Nothing here is observed or measured. Every answer is derived from how you describe the seven links. If you change one answer, the predictions change with it. That is the whole idea: the structure of a system determines the failures available to it.

New here? and answer seven plain questions. You will have a result in about a minute.

The seven links

A recognition act is any moment where a rule is applied to a case and a status is conferred: a judge ruling, an inspector certifying, a coder assigning a diagnosis. The seven links are the parts such an act needs.

The only question you answer per link

For each link you pick one of three answers. This is the single most important thing to get right, so take it slowly.

AnswerMeansAsk yourself
internal The system spells this out, and it happens under the system's own authority. "Does the document itself define this, and control it?"
external It happens, but the system neither specifies nor governs it. "Does this happen somewhere else, outside this document's control?"
absent There is no such link at all. "Does this simply not exist for this system?"

A gene ontology has no judge and no appeal, so its assessor and remedy are absent. A certification scheme usually has an appeals process it does not itself run, which makes remedy external. Court rules run their own appeals, which makes remedy internal.

Reading the result grid

The result is a grid: four strata (A–D, kinds of failure) down the side, eight loci (the seven links plus the artifact body) across. Each cell says whether that kind of failure can occur at that place.

The two "nothing here" marks are not the same, and the difference matters.

  • · not a well-formed crossing — this coordinate does not exist for any system. Stratum D at the artifact body is always ·, because a recognition failure cannot live in a document that confers no status. This is a fact about the kernel.
  • ∅ no such link in this system — the coordinate exists and the failure could sit there, but this system has no such link. This is a fact about your system, not about the kernel.

Concretely: a gene ontology shows ∅ for inconsistency at authority. That does not mean the ontology cannot be inconsistent. It means it has no authority link for the inconsistency to sit at — so the failure relocates to the artifact body, where the same row reads ✓. Read the whole row, never a single cell.

The four strata

Stratum D is gated: its failures need a real recognition act to occur. That is why a system with no act shows ✗ cannot fire across D — the failure is barred, not merely relocated. A, B and C are ungated and always have the artifact body to fall back on.

Declared vs computed kind

You may declare what you think your system is. The kernel works out the kind independently, from the links alone, and reports both. When they disagree you get a kind mismatch banner. That disagreement is a finding, not an error to be corrected — it usually means the system does less than it claims.
